# 检修动态避让规格（规则定死版）

状态：已定稿，待实现
适用模块：`cspplant/field`（作业票、动态避让求值、退出/放回编排）、`cspplant/heliostat`（落点/扫描走廊几何）、`cspplant/audit`（依据与审计）、`cspplant/console`（展示）

本文件把需求逐条锁死。凡写"必须/禁止"的条目都是验收项，实现与测试以本文为准，不接受代码里出现与本文相反的默认行为。

---

## 0. 需求可追溯性（先对账，后设计）

| # | 原始诉求 | 锁定结论 |
|---|---|---|
| R1 | 手动画圈会跟着人走，时间一长有人被晃 | 取消"人挂圈"模式，改为作业票驱动：系统按**作业时段 + 作业推进位置**自动算受扫镜组，提前退聚焦 |
| R2 | 提前退、走开再放回 | 计划轨迹前瞻 `lead_s` 预退出；放回必须同时满足"作业结束 + 人已离开"两条件 |
| R3 | 位置变了立即重算还是下一轮生效，按作业类型定 | 分三类作业，见 §3，类型由作业票携带、开取后不可改 |
| R4 | 退出与放回有时序不能乱 | 每镜状态机 + 批次栅栏，先确认退出到位才准入，先确认人走才放回，见 §5 |
| R5 | 每次退出依据与审计一致 | 每次求值产出**不可变求值记录**（evaluation id），动作命令必须引用求值 id；审计能 1:1 复算，见 §6 |
| R6 | 手动接管的镜子不许被动 | 自动避让**禁止**向手动镜下发任何姿态命令；命中即联锁阻断作业并告警，见 §6 |
| R7 | 退出/放回供控制台展示并落审计 | 求值与动作双事件上 `eventbus`、写 audit 流水、进控制台，见 §7 |
| R8 | 作业中断按未完成（部分失败）处理 | 中断票保持避让不自动放回，必须人工显式处置，见 §8 |
| R9 | 避让按时段还是按实际位置，定死 | **两者不是二选一：时段是使能闸门，位置是几何依据；计划位置管提前量，实际位置管即时修正与安全扩张。** 见 §2 |

## 1. 术语与数据模型

### 1.1 检修作业票（MaintenanceTicket）

```
ticket_id          作业票号（全局唯一）
job_type           A_HAZARD / B_ROUTINE / C_NOLIGHT（开取后不可改）
status             SCHEDULED | ACTIVE | SUSPENDED | INTERRUPTED | COMPLETED | ABORTED
planned_start, planned_end    计划时段（epoch 秒）
actual_start, actual_end      实际开/收工
route             计划轨迹：[(t, x, y, uncertainty_m), ...] 分段线性
crew_radius_m     人员安全包络半径（含人与工具，默认配置）
hazard_level      作业类型绑定的照射限值（决定扫描判定阈值）
operator, permit  负责人与许可编号（审计字段，不可空）
```

约束：
- 没有有效作业票，现场任何位置都**不得**触发自动退聚焦，也**不得**因此告警到镜场动作链路（防止"影子避让"）。
- 同一空间区域内，A 类票与任何其它票互斥，开取即拒；B 类票允许时间不相交的并存。
- 票一旦 `ACTIVE`，`job_type` 与 `route` 冻结；要改路线必须先收票再开新票（防止"换路线不重算"）。

### 1.2 位置源

- 每个 `ACTIVE/SUSPENDED` 票必须周期性上报实际位置 `(t, x, y, uncertainty_m)`；超时未报按 §8 处理。
- 位置用于两件事：**即时修正**（实际偏离计划）与**安全扩张**（不确定半径、丢失）。

### 1.3 受扫镜组（swept set）

一次求值输出：
- `planned_swept`：未来 `lead_s` 内计划轨迹会扫到的镜子；
- `actual_swept`：当前实际位置包络此刻正在扫到的镜子；
- `required_defocus = planned_swept ∪ actual_swept`（本轮必须处于退出态的全集）。

## 2. 定死规则：时段使能 + 位置判几何（回答 R9）

**禁止**把规则实现成"只按时间段"或"只按实时位置"中的任一种。固定为：

1. **时段是使能闸门**
   - `now < planned_start - lead_s`：票为 `SCHEDULED`，不产生任何退出命令（可展示预告）。
   - `planned_start - lead_s ≤ now ≤ planned_end`：使能，允许退出；退出在进入前 `lead_s` 预动。
   - 超过 `planned_end` 而票未正常完工：**不自动放回**，票转 `SUSPENDED` 并告警（超时未结），退出集保持。
2. **位置是几何依据**
   - 提前量：按**计划轨迹**在 `[now, now+lead_s]` 的走廊算 `planned_swept`，保证镜子在光斑到达前转完（`lead_s ≥ 该批最长转动时间 + 通信/确认余量`，由配置给定并在审计中记录取值）。
   - 即时性：按**实际位置**算 `actual_swept`；实际偏离计划时以实际为准扩张，且集合**只增不减**地即时生效（见各类作业的生效时机 §3）。
3. **放回条件（两个都满足才允许）**
   - 票已 `COMPLETED`（或 `ABORTED` 且经许可）；**并且**
   - 实际位置包络在 `clear_dwell_s`（默认一个求值周期以上）持续离开该镜走廊，人员确认离场。
   - 计划时段结束但人还在场 → 不满足，继续避让。人走了但票没收 → 不满足，催办收票但不动镜子。

> 一句话：**到点才允许动，动哪些看位置；提前看计划，当下看实际；放回看人走，不只看钟点。**

## 3. 作业类型与生效时机（回答 R3）

| 类型 | 典型作业 | 重算触发 | 退出生效 | 放回生效 |
|---|---|---|---|---|
| **A_HAZARD** | 塔上/吸热器附近、反光面清洗、眼部暴露风险 | 位置每报一次立即重算 | **立即**，不等周期；新增受扫镜先退出后继续作业，未确认到位则联锁禁止人员推进（现场停步指令） | 下一轮 + 离场确认（放回永远保守，不做立即） |
| **B_ROUTINE** | 镜场地面巡检、换件、除草 | 每轮控制周期重算 | **下一轮生效**（最迟 `next_cycle + lead_s` 语义，见下） | 下一轮 + 离场确认 |
| **C_NOLIGHT** | 夜间/无 DNI、室内检修 | 仅在票状态变化时求值 | 不产生退聚焦命令（仅登记；若期间 DNI/追日意外恢复，自动按 B 类处置并 warning） | — |

"下一轮生效"的精确定义：
- 第 n 轮求值在控制周期边界快照输入；第 n+1 轮把第 n 轮结果下发。位置在两轮之间变化**不**插队。
- 硬边界：**任何**类型下，若实际位置显示光斑将在 `lead_s` 内到达某镜（紧迫条件），立即升级为立即重算+立即退出。即"下一轮"只在提前量充足时成立，安全侧永远可插队。

滞回防抖（防止边界上反复进退）：
- 进入 `required_defocus` 立即占；移出后须连续 `release_dwell_s`（默认 2 个周期）不在任何集合中才允许放回候选。
- A 类的进入侧不做防抖（宁早勿晚），放回侧照常防抖。

## 4. 几何判定（怎么算"被扫到"）

1. **判定对象**：每台自动镜在追日轨迹下，其反射光锥（镜面误差 + 太阳张角 + 抖动裕量）在**人员眼高平面**（默认 1.7 m，配置化）的光斑/扫描走廊。
2. **被扫定义**：光斑几何与人员包络 `disk(实际或计划位置, crew_radius_m + 不确定度 + 配置安全余量)` 相交，或照射通量超过该 `job_type` 的限值——两者满足其一即入选。
3. **前瞻走廊**：计划轨迹段扫出的 Minkowski 走廊（轨迹 ⊕ 包络半径），与每镜在 `[now, now+lead_s]` 内的光斑扫描带求交。
4. 现有 `ZoneGuard`（检修姿态落点不得落在静态避让区，见 `heliostat/zone.py`）**保留**，但职责收窄为"退出姿态选 DEFOCUS 还是 STOW"的**姿态否决器**，不再决定"退不退"。决定"退不退"的是本规格的扫描判定。
5. 几何模型与参数（眼高、光锥角、余量、限值）带 `geometry_version`，每次求值记录版本号；模型升级后历史依据仍可按旧版本复算。

## 5. 单镜状态机与退出/放回时序（回答 R4）

### 5.1 状态（每镜，相对一张票）

```
TRACKING     正常追日
DEFOCUS_PENDING   已入选，退出命令已下发，等待到位确认
DEFOCUSED    已退出到位（本票的避让态；姿态 DEFOCUS 或 STOWED）
RESTORE_PENDING   放回命令已下发，等待重新对焦确认
MANUAL_BLOCKED    该镜被手动接管，系统无法使其退出（联锁态，见 §6）
```

### 5.2 合法迁移（其它迁移一律拒绝并告警）

```
TRACKING ──入选 required_defocus──> DEFOCUS_PENDING
DEFOCUS_PENDING ──到位确认──> DEFOCUSED
DEFOCUSED ──连续 dwell 移出 + 离场确认──> RESTORE_PENDING
RESTORE_PENDING ──对焦确认──> TRACKING
任意态 ──命手动接管且本应退出──> MANUAL_BLOCKED（不发动作，只联锁）
```

### 5.3 时序栅栏（批次级，不可乱序）

退出批次（开工作业前/位置推进前）：
1. 求值冻结快照 → 生成 evaluation id（§6）；
2. 对新增镜子**逐台**下发退出（手动镜走 §6 分支，不下发）；
3. 等待**全部**非手动目标镜 `DEFOCUSED` 到位确认，超时（配置）未到位 → 该票**禁止开工/禁止推进**，联锁事件 `entry_gate_not_clear`，已退出的保持退出；
4. 全部到位后才置"可进入/可推进"，控制台放行。

放回批次（作业结束后）：
1. 票 `COMPLETED/ABORTED` + 人员离场确认（§2 两条件）；
2. 按批次（受现有 `sweep_batch` 约束，防吸热器热冲击）下发放回，每批重新对焦确认后再下一批；
3. 放回期间若有别的在途票仍覆盖该镜（求并集），该镜跳过；
4. 全部放回完成，写批次汇总审计。

并发票的退出集取**并集**：一台镜只要被任一在效票要求退出，就保持 `DEFOCUSED`；放回时逐票释放，最后一票释放才真正放回。

## 6. 依据一致、手动豁免与审计（回答 R5、R6）

### 6.1 不可变求值记录

每次求值（无论是否产生动作）写一条 `avoidance_evaluation`：
```
evaluation_id, ts, ticket_id, job_type, geometry_version,
inputs: {now, sun, dni_used(必须 durable), planned_window, actual_pos, uncertainty, lead_s},
planned_swept[], actual_swept[], required_defocus[],
manual_blocked[], posture_vetoes[](ZoneGuard 结果), model_hash
```
- `model_hash` 覆盖代码版本 + 参数，保证记录可独立复算。
- 每条退出/放回**命令**必须携带 `evaluation_id` 与 `(ticket_id, mirror)`；找不到求值记录或该镜不在其 `required_defocus` 中的命令，调度层**必须拒绝**并 `alarm`。
- 审计回放断言：对任意历史 evaluation，用其 inputs + 当时模型重算，集合必须一致；命令集合必须是求值集合的子集。这是"依据与审计一致"的机器校验口径。

### 6.2 手动接管的镜子：只许人动，不许系统动

1. 自动避让链路**禁止**对手动镜（`drive.manual=True` / 有效 `ManualLease`）下发 defocus/stow/restore。
2. 手动镜进入 `required_defocus`：
   - 不发任何姿态命令；该镜记 `MANUAL_BLOCKED`；
   - **立即联锁**：
     - 开工前发现 → 票不得转 `ACTIVE`（`manual_block_at_entry`）；
     - 作业中实际位置扩张 newly 命中 → A 类立即要求人员停步，B 类本轮内告警；
   - 仅有的两条解除路径：操作员**释放手动接管**（系统随后按退出时序使其退出），或操作员手动把该镜转到经几何校验的安全姿态并**登记确认**（系统仍不发命令，只记录该镜由人工担保）。
3. 手动租约在镜处于避让期间到期：**不得**自动放回为追日——按"该镜仍在并集内"处理，继续保持当前姿态并 warning，等其退出集释放。
4. 现有 `track()` 中 `drive.manual` 跳过的语义保留；新增的是**安全侧主动阻断**，不只是"跳过不管"。

### 6.3 审计动作词汇（component 统一为 `field`）

| action | severity | 时机 |
|---|---|---|
| `ticket_opened` / `ticket_closed` | notice | 票状态 |
| `avoidance_evaluation` | notice | 每次求值 |
| `mirror_defocus_command/done` | notice | 退出命令/到位 |
| `mirror_restore_command/done` | notice | 放回命令/对焦 |
| `entry_gate_held` | alarm | 退出未到位而试图开工/推进 |
| `manual_block_at_entry` / `manual_block_live` | alarm | 手动镜挡路 |
| `ticket_interrupted` / `ticket_overrun` / `position_lost` | warning | 部分失败类，见 §8 |
| `forced_release` | alarm | 人工强制处置未完成票 |

## 7. 控制台展示（回答 R7）

至少四个视图，数据全部取自同一份求值/动作事件（展示与审计同源，禁止各算各的）：

1. **作业票面板**：票号、类型、计划/实际时段、状态、当前位置与包络（地图叠加）、前瞻走廊。
2. **镜子视图**：每镜标注 `TRACKING / 退出中 / 已退出(依据票号+evaluation_id) / 放回中 / 手动豁免(MANUAL_BLOCKED)`；退出镜可下钻看几何依据（落/扫点坐标、相交余量、模型版本）。
3. **时序流**：退出/放回命令与确认、联锁与告警，带 evaluation 链接。
4. **未完成事项**：`INTERRUPTED/SUSPENDED/OVERRUN` 票置顶，明确"为何没放回、差谁确认"。

事件同时上 `eventbus`（供页面推送）与 audit JSONL（供回放），重启后从持久化的活动票 + 最后一次求值恢复（沿用 `field/persist.py` 的恢复模式：恢复后先重算一次再允许追日下发）。

## 8. 作业中断：部分失败，按未完成处理（回答 R8）

1. 任何非正常完工（急停、通信断、人员撤离、票超时未结）→ 票转 `INTERRUPTED`（位置/通信短时异常先 `SUSPENDED`，超阈值升级 `INTERRUPTED`）。
2. 中断瞬间：**退出集冻结且只增不减**，禁止自动放回；相关镜子保持 `DEFOCUSED`。
3. 位置丢失安全侧：用最后已知位置 + 持续增长的不确定半径扩张；超过阈值直接把包络扩张到**整条计划路线**并 `position_lost` 告警。
4. 解除只允许人工显式二选一，均记审计：
   - **恢复作业**：票回 `ACTIVE`，先重算（按 §3 该类型时机）再继续；
   - **终止作业**：票 `ABORTED`，仍须满足"人员离场确认"才走 §5.3 放回批次；未经确认强制释放要双人许可 + `forced_release` alarm。
5. 中断期间已退出与未退出的镜子分别列清单（部分失败清单），控制台未完成视图展示；中断票不允许靠"计划时段结束"自动消失。

## 9. 与现有代码的衔接

- 现有 `SweepPlanner/SweepWindow`（`field/sweep.py`）是**清洗批次**的静态窗口，语义保留；新机制为**检修票**独立模块（建议 `field/maintenance.py`：票台账 + 求值器 + 退出/放回编排），两者共用 `HeliostatDrive` 的 `excluded` 标志与 `ZoneGuard` 姿态否决，避让集合并集。
- 追日下发前置：`track()` 对焦循环必须跳过"并集中所有镜子"（现有 `drive.excluded` 跳过点扩展为多票来源）。
- DNI 口径不变：决定追日/姿态仍只用**已落盘未过期**辐照；夜间 C 类按 DNI 不满足自然不产生风险。
- 新配置项进 `FieldLimits`：`defocus_lead_s`、`release_dwell_s`、`clear_dwell_s`、`position_timeout_s`、`position_growth_m_s`、`crew_radius_m`、`eye_height_m`、A/B 类通量限值、各批次超时。

## 10. 验收测试要点（每条对一个 R）

- R1/R9：计划轨迹在未来 `lead_s` 扫到的镜提前退出；仅到时段但轨迹不扫任何镜 → 不退；人在但票未生效 → 不退不告警动作。
- R2：完工但人未离场 → 不放回；人离场且完工 → 按批放回。
- R3：B 类轮内变位置不插队、下一轮生效；构造紧迫条件 → 任何类型立即退出；A 类位置上报即重算。
- R4：退出未到位时开工被 `entry_gate_held` 拒；放回批次顺序与对焦确认齐全；多票并集最后一票才放回。
- R5：抽任一 evaluation 用存档输入复算集合一致；无 evaluation id / 镜不在集合中的命令被拒并告警。
- R6：手动镜永不收到自动姿态命令；命中时票被拦/停步；租约到期不导致被动放回。
- R7：控制台四个视图字段与审计记录同源；重启恢复后状态一致。
- R8：急停后镜子保持退出；终止+离场确认后才放回；位置丢失扩张到全路线并告警。
